SVG postcard placeholder Deterministic from registry data: source color stripe, Madrona pin watermark, campground name + region in the existing type scale, 2-3 tag glyphs from the campground's tags column. Zero network cost, no broken-state. Renders identically across all browsers. Generated server-side or inline at render time — no asset pipeline.
Implementation sketch
Backend (Python)
  • Add image_urls TEXT DEFAULT '[]' + image_verified_at TEXT to campgrounds table.
  • Extend scripts/seed_registry.py to fetch GET /facilities/{id}/media from RIDB; store first 3 photo URLs as JSON array.
  • Extend OR seed (scripts/seed_or_state.py) to extract photo URLs from existing Redux scrape — no new requests.
  • API response: SearchResponse.results[].image_urls + image_attribution.
Frontend (React)
  • New <HeroPhoto> component, rendered inside ResultCard.tsx body (only when expanded === true).
  • Wrapper has aspect-ratio: 16/9, object-fit: cover, and filter: saturate(0.85) contrast(1.03) to flatten quality variance between sources. <img loading="lazy" decoding="async"> with alt = ${name}, ${tags[0]}.
  • If image_urls.length === 0 → render <PostcardPlaceholder> instead (SVG component, deterministic from name/region/tags/source).
  • Track PostHog event card_photo_viewed on expand; compare expand→outbound-click conversion vs. control.
What we ship to measure Ship to 100% behind kill-switch flag hero_photos. Two weeks of data answers:
  • Does expansion rate lift? (do collapsed cards also get expanded more once users know photos exist?)
  • Does expand → outbound-click conversion lift?
  • Does the no-photo cohort (WA Parks) underperform — i.e., is the 9% gap a real problem?
