v1.33 Supabase Auth In progress Replace custom auth with Supabase, Bearer tokens, auto-provisioning
Feature progress0 / 9
  • ○
    Supabase project setupS
    Create project (us-west region), configure redirect URLs, note secrets.
  • ○
    Backend JWT swapM
    Replace custom HS256 validation with Supabase JWT via PyJWT. Local decode (~0.5ms), no per-request network.
  • ○
    User auto-provisioningS
    supabase_id column on users; create local record on first authenticated call. Zero FK migration.
  • ○
    Remove custom auth routesM
    Delete signup/login/logout, keep profile CRUD. Drop bcrypt.
  • ○
    Frontend Supabase clientM
    @supabase/supabase-js. Replace useAuth internals, keep AuthContextValue interface.
  • ○
    Bearer token patternM
    Replace cookie auth with Authorization: Bearer header. New authFetch() wrapper.
  • ○
    Anonymous session migrationS
    Migrate watches from session cookie via existing migrate_watches_to_user().
  • ○
    CSP updateS
    Add Supabase project ref to connect-src.
  • ○
    Account deletion updateS
    DELETE /api/auth/me also calls Supabase admin API to delete user.
Cost
Supabase free tier. ~$0/mo. Backend ~150 LOC changed; frontend ~110 LOC.
Key risks

Supabase availability becomes a dependency for login (not for ongoing sessions — local JWT validation works offline). Existing valid tokens continue working until expiry (1 hour default). Anonymous mode is unaffected.

Feature progress0 / 8
  • ○
    Playwright setup (self-hosted, free)XS
    e2e/ directory with package.json, playwright.config.ts, shared fixtures. Runs via @playwright/test in GitHub Actions.
  • ○
    Flow 1 — Upgrade smoke testM
    Anonymous → signup → /pricing → Stripe Checkout with 4242 4242 4242 4242 → PRO badge. Catches 4 of 5 v1.4 production bugs.
  • ○
    Flow 2 — Watch limit smoke testS
    Free user creates 4th watch → UpgradeModal opens with reason=watch_limit.
  • ○
    Flow 3 — Planner limit smoke testS
    Free user submits 4th planner prompt → UpgradeModal opens with reason=planner_limit.
  • ○
    Flow 4 — Cancel + reactivateM
    Pro user → Customer Portal → Cancel → subscription_expires_at rendered → Reactivate → cleared. Webhook → DB → UI loop validation.
  • ○
    Staging URL strategy + fixture seedingS
    Fly preview branches per PR + long-lived campnw-staging for nightly runs. Tests never hit production. scripts/seed_e2e_fixtures.py via Supabase Admin API + SQLite.
  • ○
    Email confirmation off in prod SupabaseXS
    Already configured. Saved to memory so future sessions don't propose email-verification waits.
  • ○
    CI integrationS
    GitHub Actions playwright.yml: smoke on every PR (~60s), nightly cron for all flows. Failures upload HTML report + trace.
Cost
$0/mo infrastructure. GitHub Actions free minutes + Fly preview branches auto-suspend. Stripe test-mode only.
Key risks

Stripe Checkout UI changes: stable but does occasionally rev. Fix the single fixture rather than adding wrapper layers.

Fixture user drift on schema changes: scripts/seed_e2e_fixtures.py is idempotent — rerun seed = fixed.

Test account email collision: Flow 1 uses timestamped random email per run; Flows 2-4 use stable purpose-named fixtures.

Live-mode bugs missed by test-mode tests: ~95% coverage. Real fraud detection, bank declines, refund processing need manual smoke when first live transaction lands.

Maestro Web perf regression doesn't affect Playwright: Playwright's iframe handling is mature and not at risk of the same beta perf trap.
